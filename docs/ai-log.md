# บันทึกการใช้ AI

สำหรับทุกคนในทีม ใช้ตอนที่ใช้ AI ช่วยงานแล้วต้องจด

โจทย์ข้อ 6 บังคับให้จดทุกครั้งที่ใช้ AI และไฟล์นี้เป็นภาคผนวกของรายงาน
**ใช้เสร็จให้จดทันที** อย่ารอมาเขียนย้อนหลัง

## กติกา

กติกาของ AI ในทีม (ทำอะไรได้ ทำอะไรไม่ได้) อยู่ใน [AGENTS.md](../AGENTS.md) ที่ไฟล์นี้มีเพิ่มแค่เรื่องการจด

1. จดทุกครั้งที่ใช้ AI ช่วยวิเคราะห์โจทย์ ออกแบบ เสนอแนวทางเขียน code อธิบาย error สร้าง test case และตรวจรายงาน
2. code ที่ส่งต้องอธิบายเองได้ทุกบรรทัด
3. ผล test กับภาพหน้าจอต้องมาจากการ run จริงเท่านั้น
4. ถ้าเอา code หรือข้อมูลมาจากที่อื่น (เว็บ, เอกสาร Python) ให้จดที่มาไว้ในช่อง "สรุปที่นำมาใช้"
5. ทีมตกลงกันว่าการให้ AI สอนเจ้าของ repo ไม่ต้องจดในไฟล์นี้ ส่วนชุด A กับชุด B จดทุกครั้ง

### #4: ให้ AI ช่วย commit, push และเปิด PR ของงานแกนกลาง

| ช่อง | รายละเอียด |
| --- | --- |
| วันที่ | 18 พ.ย. 2569 |
| ผู้ใช้ | แกนกลาง |
| เครื่องมือ | Claude (Claude Code) |
| วัตถุประสงค์ | พอเขียนโค้ดเสร็จและ test ผ่านแล้ว ให้ AI เช็กทั้งไฟล์อีกรอบ แล้วรันคำสั่ง git ให้ คือ commit, push, เปิด PR และสร้าง branch ใหม่จาก `main` ล่าสุดหลัง merge ทำไป 6 รอบ ได้ `feat: models` (#19), `feat: storage` (#20), `feat: wallet` (#21), `feat: display` (#22), `feat: wallet menu` (#23), `feat: app` (#24) |
| ตัวอย่าง Prompt | "commit pr เลย" และ "Merge แล้ว ไปต่อ storage" |
| สรุปที่นำมาใช้ | ใช้คำสั่ง git/gh ที่ AI รันให้ ข้อความ commit `feat: ...` กับคำอธิบาย PR ที่ AI ร่างจากผล test (ติ๊ก checklist ให้ 3 ข้อที่เช็กได้จากเครื่อง ส่วนข้อ "อธิบายโค้ดได้เอง" กับข้อ ai-log ติ๊กเอง) AI ไม่ได้แก้โค้ดในไฟล์ ยกเว้นลบบรรทัด comment โค้ดเก่า 1 บรรทัดใน `change_status` ก่อน commit models (ไม่เปลี่ยน logic) ส่วนการ merge กด Squash and merge เองบน GitHub รายการ ai-log นี้ AI ร่างให้ แล้วแก้ช่องวิธีตรวจสอบให้ตรงกับที่ทำจริง |
| วิธีตรวจสอบ | รัน test ของแต่ละขั้นใน python3 ตามที่ AI ให้ไว้ แล้วให้ AI รันซ้ำทั้งไฟล์ ผ่าน C1, C2, C3, C4, C5, C6, C8, C9, C10, C11, C12 บางขั้น (S5, W2, W3, D1, A3) AI เจอชื่อค่าใน config หรือชื่อ function สะกดผิดตอนเช็ก เลยแก้เองแล้วให้เช็กใหม่จนผ่าน ช่วง display กับ app ให้ AI รัน test ใน Terminal ของแอป Claude ให้ดูไปพร้อมกัน (หน้าจอของเพื่อนที่ยังไม่เสร็จใช้ตัวปลอมแทนชั่วคราว) ก่อนกด merge เปิดแท็บ Files changed ดูว่าแก้แค่ไฟล์ที่ตั้งใจและตรงกับที่เขียนเอง |

### #5: ให้ AI ออกแบบและเขียน doc, md กับ comment ใหม่ทั้ง repo

| ช่อง | รายละเอียด |
| --- | --- |
| วันที่ | 19 พ.ย. 2569 |
| ผู้ใช้ | แกนกลาง |
| เครื่องมือ | Claude (Claude Code) แบ่งงานเป็นหลาย session และใช้ reviewer ของ egm ช่วยตรวจ |
| วัตถุประสงค์ | สำรวจ doc เดิมทุกไฟล์ ออกแบบโครงเอกสารใหม่ (13 ไฟล์ เพิ่ม `docs/04-submit.md` กับ `docs/05-contracts.md` รวม `docs/ai/` เข้า `docs/tasks/`) กำหนดสัญญาระหว่างชุด แล้วเขียน md, docstring และ comment ใหม่ทั้งหมด โดยไม่แตะโค้ด |
| ตัวอย่าง Prompt | "งั้นช่วยยกเครื่อง docs หรือ md หรือ comment ในไฟล์ทุกไฟล์ทุกอย่างทั้งหมดใน repo ใหม่ ให้เป็นรูปแบบที่ออกแบบเลย" และ "โดยใช้ skil egm ออกแบบทำให้สมบูรร์แบบมากที่สุด" |
| สรุปที่นำมาใช้ | ใช้โครงเอกสาร สัญญาระหว่างชุด กฎเพิ่มของชุด A/B และข้อความที่ AI เขียน หลังจากตอบคำถามตัดสินใจเองตอนอนุมัติแบบ (เลือกตามที่ AI แนะนำทุกข้อ) ในไฟล์ `.py` เปลี่ยนแค่ docstring กับ comment ส่วนจุดที่ AI เจอว่าโค้ดแกนกลางยังไม่ตรง doc เขียนไว้ตามจริงก่อน แล้วจะแก้ใน PR แยก |
| วิธีตรวจสอบ | AI เช็กด้วย script ว่าโค้ดใน `.py` ทั้ง 24 ไฟล์เหมือนเดิม (เทียบ AST กับ commit `632c91f`), ลิงก์ใน md ไม่เสีย, ตัวเลขตรงกับ `config.py`, รายการ #1–#4 ใน ai-log ไม่ถูกแก้ และ `python main.py` ทำงานเหมือนเดิม - อ่านสรุปทางเลือกแล้วตอบคำถามตัดสินใจเองทุกข้อตอนอนุมัติแบบ และก่อนกด merge เปิดแท็บ Files changed อ่าน diff เอง |

### #6: แก้จุดที่โค้ดแกนกลางยังไม่ตรง doc ให้ AI เสนอวิธีแก้ แก้ doc ตาม และช่วยเปิด PR

| ช่อง | รายละเอียด |
| --- | --- |
| วันที่ | 19 พ.ย. 2569 |
| ผู้ใช้ | แกนกลาง |
| เครื่องมือ | Claude (Claude Code) |
| วัตถุประสงค์ | ไล่ 5 จุดที่ doc จาก #5 เขียนไว้ว่าโค้ดแกนกลางยังไม่ตรง ให้ AI เช็กกับโค้ดจริงแล้วเสนอวิธีแก้ให้เลือก พอแก้โค้ดเองเสร็จแต่ละจุด ให้ AI รัน test ซ้ำ แก้ docstring กับ doc ให้ตรงกับโค้ด แล้ว commit, push, เปิด PR |
| ตัวอย่าง Prompt | ตอน AI ถามวิธีแก้ เลือกตอบ "เขียนไฟล์ก่อน (Recommended)" และพอแก้แต่ละจุดเสร็จ พิมพ์ "F4 แก้แล้ว เช็กให้หน่อย" |
| สรุปที่นำมาใช้ | เลือกวิธีแก้ตามที่ AI แนะนำทุกข้อ: `add_transaction` เขียนไฟล์ก่อนแล้วค่อยเพิ่มเข้า memory, `append_log` เติม `[!]`, `load_csv` จับ `TypeError` กับ `AttributeError` เพิ่ม, `app.run()` ครอบ `load_all()` ด้วย `try` แยก (กด Ctrl+C ตอนโหลดออกเลยโดยไม่ save) ส่วน `screen_wallet` คงไว้ตาม SC3 และ `EOFError` ยังอยู่นอกขอบเขตตาม IN4 โค้ด 4 จุดแก้เอง ส่วน docstring กับ doc (`docs/tasks/core.md`, `docs/05-contracts.md`, `docs/02-design.md`) AI แก้ให้ตรงกับโค้ด และลบหัวข้อ "ข้อจำกัดที่รู้อยู่แล้ว" ใน `core.md` ออก |
| วิธีตรวจสอบ | รัน test ของแต่ละจุดใน terminal โดยบังคับให้เกิด error จริง (path ที่ไม่มีอยู่, CSV ที่ column ไม่ครบ, ส่งสัญญาณ Ctrl+C ตอนโหลด) แล้วให้ AI รันซ้ำใน Terminal ของแอป Claude ให้ดู รอบแรกของ `load_csv` กับ `app.run()` จับ error ผิดตัว AI เช็กเจอ เลยแก้เองแล้วให้เช็กใหม่จนผ่าน AI เทียบ AST ว่าโค้ดเปลี่ยนแค่ 3 ไฟล์ที่ตั้งใจ ผ่าน C1, C2, C3 และ `python main.py` ยังหยุดที่ TODO ของชุด B เหมือนเดิม - ก่อนกด merge เปิดแท็บ Files changed อ่าน diff เอง |
